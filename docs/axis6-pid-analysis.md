## 仿真范围与复现

运行：

```powershell
python tools/simulate-axis6-pid.py
```

脚本使用现有Python和Matplotlib，不安装依赖、不连接硬件、不修改固件。CSV、数值记录和图像输出到已忽略的 `build/axis6-pid-analysis/`。

**这是归一化机理对照，不是X35S数字孪生，也未拟合实际日志。下列增益、误差、输出和时间全部是归一化量，不能写入驱动器。**

假设位置目标为0，惯量为1、黏性阻尼为1.2、静/动摩擦为0.08/0.06；t=1时施加速度增量0.6的瞬时冲击，并从此施加恒定负载0.5。持续负载是独立假设，不能由用户观察到瞬时冲击直接推断。模型为：

```text
e = -position
I = clamp(I + Ki*e*dt, -integral_limit, integral_limit)
u = clamp(Kp*e + I - Kd*velocity, -output_limit, output_limit)
acceleration = motor_gain*u - load - 1.2*velocity - friction
```

近零速时，净力不超过静摩擦则保持静止；运动时使用动摩擦，过零时检查能否停止。积分只做限幅，未复制Emm内部积分分离、抗饱和、滤波或模式切换。默认Kd=3、输出上限2、积分输出上限2、motor_gain=1，步长0.001。

| 模型对照 | Kp / Ki | 变更的限制 | t=30时误差绝对值 |
| --- | --- | --- | ---: |
| 无积分 | 4 / 0 | 默认 | 0.109993 |
| 只增大Kp | 8 / 0 | 默认 | 0.058937 |
| 较弱积分 | 4 / 0.1 | 默认 | 0.076106 |
| 较强积分 | 4 / 2 | 默认 | 0.001327 |
| 输出受限 | 4 / 2 | 输出上限0.5 | 0.115021 |
| 受限后继续增益 | 8 / 4 | 输出上限0.5 | 0.127003 |
| 积分受限 | 4 / 2 | 积分输出上限0.03 | 0.102493 |

在该假设模型里，增大Kp减小静差，积分充分且输出有余量时静差明显收敛；输出饱和或积分受限时，仍可能保持残差。不能把残差简单归结为Kp或Ki偏小。积分消除恒定偏差的机理及积分限幅的影响，可参见[NI伺服整定说明](https://www.ni.com/en/support/documentation/supplemental/12/understanding-servo-tune.html)；这不是Emm内部算法说明。

还验证了不可识别性：将PID及两个输出限幅一起乘10，同时把motor_gain除以10，得到的位置轨迹与原模型最大差仅 `3.32e-15`。所以未知执行器增益时，即使位置曲线完整，也不能唯一反推出驱动PID数字。

## 验证与结论

- 模型趋势、输出/积分限制、增益缩放等价自检通过；步长减半后各案例末值最大差 `0.000221237`，在该模型自检门槛0.002以内。
- 现有完整CTest通过17/17。此次未修改生产代码，因此未重新构建Keil或Android，不打包、不烧录、不推送。
- **未确定实机PID，也未确认Kp或Ki不足是故障原因。** 归一化仿真只验证几种可能机制；模拟自检和CTest都不能代替实机辨识。
- 若要继续定量整定，应先在停止指令之前记录本机PID读回、驱动0x34/0x37、实际位置/速度及支持读取的电流或输出量，并取得电机/传动/负载参数或可辨识的动态响应。先确认有无输出饱和与机构干涉，再比较单变量增益调整的响应。
- 此前建议的Kp=19800仅是未验证的试调候选，本次没有通过仿真认可该数值；默认参数也不代表已证明适合当前负载。
