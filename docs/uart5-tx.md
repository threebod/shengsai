# UART5上位机发送队列

UART5仍使用115200、8N1及原`AA 55`二进制帧。主循环负责组包、CRC和整包入队；UART5的TXE中断每次只搬运一个字节，队列空时关闭TXE，新包入队后重新开启。中断不格式化日志、不解析请求、不执行动作。`serialSendString`不再等待UART5的TC标志。

固定发送环形缓冲为1024字节，保留一个空位区分满/空，实际容量1023字节。整包复制完后才发布写指针，并使用内存屏障；队列满时立即返回失败，已经在队列里的帧不被覆盖或插入半包。

实时日志和周期状态不能占用最后两个最大帧的空间，给控制应答及完成事件留余量。实时日志满时可不发送，原任务RAM日志仍先写入，之后可以通过“读取上次任务日志”获取；状态恢复空间后发送最新快照。队列满时，控制应答保留待后续主循环发送，不重新执行命令；完成事件仅在成功入队后清除。未发送的完成事件会先于下一项运动处理，避免被覆盖。

每轮上位机服务最多处理64个RX字节、2个有效请求。发送空间不足以容纳最大应答时暂停取出新请求，主循环继续运行其他服务。已有请求缓存继续防止重复执行。RX环形缓冲若实际溢出，沿用停止和清空接收状态的处理，并记录`ERR HOST: RX queue overflow; stopped`。持续输入超过链路输出能力仍可能触发该保护，不能把固定缓冲理解为无限吞吐。

UART4视觉通信本次保持原样，包括9600波特率、逐字节发送、RX中断和视觉首帧计时。30字节视觉帧的约31.25ms线速时间仍存在，本次仅去掉UART5对主循环的发送等待。电机速度、加速度、反馈门槛、反馈查询节拍和协议载荷不变。

## 验证

`host_uart`测试编译生产发送队列和请求服务，覆盖中断在发布前执行、CRC完整帧、1000轮回绕、队列满拒绝且不改写、TXE空闲关闭与重启、应答预留、64字节/2帧预算、拥塞时请求背压和缓存、应答待发与完成事件顺序、RX溢出及点动超时。UART4初始化、发送和RX中断函数以及视觉跟踪运行文件与改动前逐段/逐字节比较一致。

软件测试和Keil构建通过后，实车仍需比较持续读取日志、心跳/状态通信下的动作衔接、实际5/6轴查询间隔、丢帧和CRC错误。当前未烧录、未进行这项实机压力测试，不能给出实际耗时减少量。
