# 圆环近中心平均速度修正

2026-11-01：单轴入范围停止修正后，用户新日志仍显示同一圆环会话持续42.563秒，266条PIX记录，du为-3～+5、dv为-5～+5，没有IN_RANGE结束记录，另有9次帧过期停车。初期可见du长期在0/+1附近而dv反复跨越0～+1区间，说明仅停止已合格方向不足以消除近中心往复。

原控制把低于0.5RPM、取整为0的非零修正持续抬到1RPM，0.5～1RPM的速度也会连续四舍五入为1RPM。新控制仅对圆环的低于1RPM速度按实际控制间隔累计，以0/±1RPM交替输出，使平均值接近计算值；例如计算0.25RPM，在均匀10ms节拍下约每四个周期输出一个1RPM周期。1RPM以上保留原取整、加减速、各轮修调及总轮速上限。方向反转、进入容差、丢帧停车或结束时清除累计余量，避免旧方向积累延续。

仍是同一个连续跟踪会话，不增加固定停车稳定、普通重采样或第二轮位置微调；验收仍按原始实际像素，横纵各0～+1，连续三帧有效新鲜结果才完成。物料控制、15RPM、10ms控制周期、350ms新鲜度、1000ms首帧期限及IMU/CAN/急停保护保持原值。未修改标定比例、相机或上位机协议。

关于刷新速度：10ms是控制计算的节拍下限；视觉帧常为约100～190ms到达，PIX仅对TRACK按100ms限频，并非完整控制记录。速度变化才发送四轮速度加同步指令，驱动持续保持未改变的指令。CAN每包等待发送完成，最多50次100us后故障停止；实际正常下发耗时需实机记录，不能只凭设定周期排除调度或驱动响应延迟。

PIX新增cmd、m1～m4、ctrl_ms和tx_ms，继续只写现有RAM任务日志。m1～m4是记录时最近一次成功同步发送的四轮有符号RPM指令，包含修调，既非本帧重新计算后的命令也非真实轮速反馈；cmd=0表示该缓存无效，不能将占位0当作反馈。ctrl_ms为最近一次跟踪控制计算的实际间隔，tx_ms为最近一次成功四轮速度及同步批次的发送耗时，单位ms；本次帧还未驱动过时可能显示0，速度不变时不会重发，tx_ms会保留上次值。这些字段可以辅助区分视觉延迟、控制调度和CAN下发，不用于测量电机机械响应。

验证：先在旧代码复现0.25RPM计算值变成持续1RPM的回归失败。延迟模型使用190ms回帧、100ms图像延迟；在1～3倍运动响应、9组正负起点的27个场景中新控制均完成三帧确认；旧控制在2～3倍响应的多组场景中持续30秒未完成。模型倍率用于敏感性验证，不是实车标定结果，也不能单独证明实车振荡的唯一原因。测试还覆盖不均匀控制间隔的平均输出、出界恢复、方向与丢帧保护及日志字段；生产服务测试改为核对小偏差累计运动，允许低速周期输出0。
